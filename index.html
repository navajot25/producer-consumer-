Operating Systems Practical & Viva Reference Guide

Producer-Consumer Problem, Bounded Buffer, Counting & Binary Semaphores

Producer-Consumer Metaphor Mapping

OS Concept Uber Dispatch Equivalent Mathematical Operation
Producer Rider Booking App (Aarav, Priya, Sneha) Generates ride requests and enqueues them into buffer
Consumer Driver Partner Portal (Amit, Rohan, Neha) Accepts and fulfills requests from the queue (FIFO)
Bounded Buffer Cloud Dispatch Queue Fixed size array holding waiting rides ($N$ slots)
empty (Semaphore) Available slots Counts free slots in buffer (init = $N$, decremented by rider)
full (Semaphore) Waiting rides Counts pending rides (init = $0$, incremented by rider)
mutex (Binary Semaphore) Queue Access Lock Guarantees only 1 rider or driver modifies queue at a time (init = $1$)

Algorithm Pseudo-Code (C / POSIX Semaphores)

// PRODUCER (RIDER)
wait(empty);    // Ensure space exists in buffer
wait(mutex);    // Lock critical section
buffer[in] = ride_item;
in = (in + 1) % N;
signal(mutex);  // Release lock
signal(full);   // Wake up waiting drivers

// CONSUMER (DRIVER)
wait(full);     // Ensure at least 1 ride is ready
wait(mutex);    // Lock critical section
ride_item = buffer[out];
out = (out + 1) % N;
signal(mutex);  // Release lock
signal(empty);  // Wake up waiting riders

Frequently Asked Viva & Exam Questions

Why must wait(empty) happen BEFORE wait(mutex)?

If a rider executes wait(mutex) first when the buffer is already full ($empty = 0$), it locks the queue and then gets blocked on wait(empty) while still holding the Mutex lock. A driver wanting to accept a ride to free up space cannot acquire the lock, resulting in a fatal Deadlock!

What is a Race Condition in ride booking?

If two drivers check the queue simultaneously without a Mutex lock, both drivers might read and accept the exact same ride request, resulting in duplicate booking, driver dispute, and corrupted queue pointers.

What are the initial values of the semaphores?

For a bounded buffer of capacity $N$: empty = N (all slots free), full = 0 (no items produced yet), and mutex = 1 (queue unlocked).

Is this solution Starvation-Free?

Yes. Because the Semaphore wait queues use First-In, First-Out (FIFO) ordering, any thread that blocks is guaranteed to be serviced as soon as slots or items become available.
